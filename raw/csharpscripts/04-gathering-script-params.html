Получение адреса СП, идентификатора сессии и пользовательских данных

Для исполняемых типов приложений cлужба выполнения скриптов, в общем случае, передает два аргумента:

  • -a адрес сервера приложений
  • --session идентификатор пользовательской сессии

В рамках работы с системой отчетов пользовательские данные (userData) передаются в стандартный поток ввода. Данные унифицированы в формат JSON имеют следующий вид: 

{
  "object_ids": [1012, 2, 3],
  "params": {
    "Accuracy": "2",
    "Depth": "3",
    "LinkType": "Состоит из ..."
  },
  "conf_rules": {
    "rule_id": 10,
    "final_product_id": 200,
    "path": [5, 6, 7],
    "rule_params": [
      {
        "param_name": "Color",
        "param_type": 1,
        "param_value": "Red",
        "is_any": false
      },
      {
        "param_name": "Size",
        "param_type": 2,
        "param_value": "XL",
        "is_any": true
      }
    ],
    "fixed_context_id": 99
  }
}
- object_ids — список идентификаторов объектов, по которым необходимо сформировать отчет; - params — словарь параметров, определенных администратором при регистрации отчета и их значения, заполненные пользователем при запуске отчета. Применительно к нашему примеру, в списке параметров находятся: - Depth — глубина обхода ЭСИ - LinkType — тип связи для получения дочерних объектов - Accuracy — точность округления значений атрибутов - conf_rules — правила версионного конфигурирования

Для упрощения работы с входными аргументами и пользовательскими данными создадим универсальный класс, который можно будет переиспользовать в других проектах.

Для упрощения дальнейшей работы с этим утилитарным классом, внесем несколько улучшений в сгенерированный код:

1) Заменим все массивы на списки. Подробную информацию о типах данных C# можно получить по ссылке - https://learn.microsoft.com/ru-ru/dotnet/csharp/fundamentals/types/

Например: 

public int[] object_ids { get; set; }
заменим на: 
public List<int> object_ids { get; set; }

2) Для читаемости и соблюдения правил именования в C# заменим все имена полей в нижнем регистре и с нижним подчеркиванием (snake_case) на PascalCase - https://learn.microsoft.com/ru-ru/dotnet/csharp/fundamentals/coding-style/identifier-names

Например: 

public List<int> object_ids { get; set; }
заменим на: 
public List<int> ObjectIds { get; set; }

3) В результате выполненных изменений упрощается работа с объектом, но пропадает сквозное соответствие полей в JSON и полей в классе приложения, поскольку "object_ids" ≠ ObjectIds. Поэтому нужно «подсказать» приложению как связывать поля. Это реализуется с помощью атрибута «JsonPropertyName» (https://learn.microsoft.com/ru-ru/dotnet/standard/serialization/system-text-json/customize-properties)

Например: 

public List<int> ObjectIds { get; set; }
заменим на: 
[JsonPropertyName("object_ids")]
public List<int> ObjectIds { get; set; }
4) Для возможности работы с элементами коллекции в C# она должна быть инициализирована (под нее должна быть выделена память).
(https://learn.microsoft.com/ru-ru/dotnet/csharp/language-reference/builtin-types/collections)

У нас в объекте несколько коллекций: 

List<int> ObjectIds
Dictionary<string, string> Params
List<RuleParam> RuleParams

Все эти наборы данных есть во входном JSON, поэтому коллекции инициализируются автоматически. Но лучше перестраховаться, и выделить под них память заранее, чтобы исключить экзотические случаи NullReferenceExeption (https://learn.microsoft.com/ru-ru/dotnet/api/system.nullreferenceexception?view=net-8.0)

Например: 

public List<int> object_ids { get; set; }
заменим на: 
List<int> ObjectIds { get; set; } = new();
5) Так как ConfRules в ряде сценариев будет пустым и не будет использоваться – пометим ConfRules как тип, допускающий null. (https://learn.microsoft.com/ru-ru/dotnet/csharp/language-reference/builtin-types/nullable-value-types) 
[JsonPropertyName("conf_rules")]
public ConfRules ConfRules { get; set; }
заменим на: 
[JsonPropertyName("conf_rules")]
public ConfRules? ConfRules { get; set; }
6) Добавим в объект четыре дополнительных поля, два из которых уже есть во входном JSON, но мы будем использовать строго-закодированные, для стабильности приложения: 
public string ApiVersion { get; set; } = "3"; 
public int RequestTimeoutSeconds { get; set; } = 60;
public string AppServerHost { get; set; } = "http://localhost:8076"; //по умолчанию заполнено локальным адресом, но переопределяется входным параметром «-а»
public string SessionId { get; set; } //в готовом приложении должно оставаться пустым и заполнятся из входного параметра --session.

Теперь нужно создать вспомогательные методы для заполнения этого объекта и получения из него данных. Служба выполнения скриптов будет запускать это приложение с такими параметрами: 
./ExactProductStructureReport -a http://host:port –session 4e19c13d-cab0-467b-8776-423eaee61f2a
При этом в приложение через стандартный поток ввода будет передан JSON c пользовательскими данными, необходимыми для формирования отчета .

В первую очередь сделаем метод(функцию) парсинга входных аргументов. Метод должен принимать массив аргументов, искомый ключ и возвращать значение: 

private static bool TryGetArgumentValue(string[] arguments, string argumentKey, out string value)
{
    value = string.Empty;
    for (int i = 0; i < arguments.Length - 1; i++)
    {
        if (string.Equals(arguments[i], argumentKey, StringComparison.OrdinalIgnoreCase))
        {
            value = arguments[i + 1];
            return true;
        }
    }
    return false;
}
Фактически мы проходим по всему массиву входных аргументов и если встречаем искомый аргумент, то следующий после него элемент считаем значением этого аргумента. То есть вот эти входные аргументы: 
-a http://host:port –session 4e19c13d-cab0-467b-8776-423eaee61f2a
Будут преобразованы в массив: 
["-a", "http://host:port", "–session", "4e19c13d-cab0-467b-8776-423eaee61f2a"]
И при поиске и нахождении, например, аргумента «-a», мы будем считать, что следующим за ним элемент это адрес сервера приложений. В нашем случае «http://host:port».

Следующим шагом добавим метод получения конкретных аргументов: 

private static void ApplyCommandLineArguments(AppConfigurations config, string[] arguments)
{
    if (TryGetArgumentValue(arguments, "-a", out var host))
        config.AppServerHost = host;

    if (TryGetArgumentValue(arguments, "--session", out var sessionId))
        config.SessionId = sessionId;
}

Теперь добавим метод обработки пользовательских данных: 

private static AppConfigurations DeserializeFromJson(string? userData)
{
    if (string.IsNullOrWhiteSpace(userData))
        return new AppConfigurations();
    var json = userData.TrimStart('\ufeff').Trim();
    return JsonSerializer.Deserialize<AppConfigurations>(json) ?? throw new InvalidOperationException("JSON конфигурации пустой или некорректный");
}
Если userData пустой или включает только пробелы, то возвращаем AppConfigurations с настройками по умолчанию (которые мы строго задали). А если во входной строке присутствует JSON, то:

  • удаляем возможный BOM (Byte Order Mark - используется для указания кодировки, но в UTF-8 не обязателен и часто мешает при обработке данных)
  • десериализуем строковый Json в объект AppConfigurations
    (https://learn.microsoft.com/ru-ru/dotnet/standard/serialization/system-text-json/deserialization)

Осталось создать основной метод получения полной конфигурации: 

public static AppConfigurations GetConfiguration(string[] arguments, string? userData)
{
    try
    {
        var config = DeserializeFromJson(userData);
        ApplyCommandLineArguments(config, arguments);
        return config;
    }
    catch (Exception ex)
    {
        throw new InvalidOperationException(
            "Ошибка при разборе конфигурации приложения",
            ex
        );
    }
}
В этом методе мы просто пытаемся вызвать методы десериализации JSON и парсинга аргументов и заполнить весь объект AppConfigurations, а при неудаче возвращаем ошибку. (https://learn.microsoft.com/ru-ru/dotnet/csharp/language-reference/statements/exception-handling-statements https://learn.microsoft.com/ru-ru/dotnet/csharp/fundamentals/exceptions/exception-handling)

Финальный код класса получения и хранения настроек (AppConfigurations.cs) приложения выглядит следующим образом: 

using System.Text.Json;
using System.Text.Json.Serialization;

namespace ExactProductStructureReport
{
    public class AppConfigurations
    {
        public string ApiVersion =>
                                Params != null &&
                                Params.TryGetValue("ApiVersion", out var v) &&
                                !string.IsNullOrWhiteSpace(v)
                                    ? v
                                    : "4";
        public int RequestTimeoutSeconds =>
                        Params != null &&
                        Params.TryGetValue("RequestTimeoutSeconds", out var t)
                            ? Convert.ToInt16(t)
                            : 60;
        public string AppServerHost { get; set; } = "http://localhost:8076";
        public string SessionId { get; set; }
        [JsonPropertyName("object_ids")]
        public List<int> ObjectIds { get; set; } = new();
        [JsonPropertyName("params")]
        public Dictionary<string, string> Params { get; set; } = new();
        [JsonPropertyName("conf_rules")]
        public ConfRules? ConfRules { get; set; }

        public static AppConfigurations GetConfiguration(string[] arguments, string? userData)
        {
            try
            {
                var config = DeserializeFromJson(userData);
                ApplyCommandLineArguments(config, arguments);
                return config;
            }
            catch (Exception ex)
            {
                throw new InvalidOperationException(
                    "Ошибка при разборе конфигурации приложения",
                    ex
                );
            }
        }

        private static AppConfigurations DeserializeFromJson(string? userData)
        {
            if (string.IsNullOrWhiteSpace(userData))
                return new AppConfigurations();

            var json = userData.TrimStart('\ufeff').Trim();

            return JsonSerializer.Deserialize<AppConfigurations>(json)
                   ?? throw new InvalidOperationException("JSON конфигурации пустой или некорректный");
        }

        private static void ApplyCommandLineArguments(AppConfigurations config, string[] arguments)
        {
            if (TryGetArgumentValue(arguments, "-a", out var host))
                config.AppServerHost = host;

            if (TryGetArgumentValue(arguments, "--session", out var sessionId))
                config.SessionId = sessionId;
        }

        private static bool TryGetArgumentValue(
    string[] arguments,
    string argumentKey,
    out string value)
        {
            value = string.Empty;

            for (int i = 0; i < arguments.Length - 1; i++)
            {
                if (string.Equals(arguments[i], argumentKey, StringComparison.OrdinalIgnoreCase))
                {
                    value = arguments[i + 1];
                    return true;
                }
            }

            return false;
        }
    }

    public class ConfRules
    {
        [JsonPropertyName("rule_id")]
        public int RuleId { get; set; }

        [JsonPropertyName("final_product_id")]
        public int FinalProductId { get; set; }

        [JsonPropertyName("path")]
        public List<int> Path { get; set; } = new();

        [JsonPropertyName("rule_params")]
        public List<RuleParam> RuleParams { get; set; } = new();

        [JsonPropertyName("fixed_context_id")]
        public int FixedContextId { get; set; }
    }

    public class RuleParam
    {
        [JsonPropertyName("param_name")]
        public string ParamName { get; set; } = string.Empty;

        [JsonPropertyName("param_type")]
        public int ParamType { get; set; }

        [JsonPropertyName("param_value")]
        public string ParamValue { get; set; } = string.Empty;

        [JsonPropertyName("is_any")]
        public bool IsAny { get; set; }
    }
}
