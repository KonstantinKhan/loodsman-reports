Структура и служебные классы шаблона

Этот раздел описывает архитектуру и ключевые компоненты шаблона скрипта для ЛОЦМАН:PLM, который использует прямое взаимодействие с сервером приложений через библиотеку Ascon.Plm.ServerApi и механизмы маппинга данных.
Понимание структуры этих классов необходимо для разработки новых отчётов и сервисов.

Global.cs

Этот файл содержит глобальные настройки приложения, которые используются во всём проекте.
Центральным элементом здесь являются настройки сериализации JSON.

  • Статический класс Global
    • Назначение: Предоставляет единые, предопределённые настройки для сериализации и десериализации JSON во всех компонентах приложения.
      Это обеспечивает консистентность формата данных и упрощает их чтение.
    • Ключевое свойство:
      • JsonSerializerOptions: Статическое, доступное только для чтения поле, содержащее объект JsonSerializerOptions.
        • WriteIndented = true: Форматирует JSON с отступами и переносами строк для удобного чтения человеком.
          Без этой настройки JSON будет выводиться в одну строку.
        • PropertyNameCaseInsensitive = true: Делает десериализацию нечувствительной к регистру имён свойств.
          Например, свойство C# Product может быть успешно заполнено из JSON-поля "product".
        • PropertyNamingPolicy = JsonNamingPolicy.CamelCase: Автоматически преобразует имена свойств C# в стиль camelCase.
          Например, свойство C# FirstName можно успешно сериализовать в JSON-поле "firstName".
        • Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping: Ослабляет экранирование символов в JSON.
          Это позволяет сохранять кириллицу и другие символы Unicode в читаемом виде (как есть), а не в виде escape-последовательности типа \uXXXX.

Models.cs

Этот файл содержит все объектные модели (DTO - Data Transfer Object), используемые для обмена данными с сервером приложений ЛОЦМАН:PLM, а также внутренние модели для хранения данных отчёта.
Все модели используют атрибуты [Column] и [ColumnNullable] из библиотеки Ascon.Plm.Mapping для точного сопоставления полей с данными, возвращаемыми из Server API.

В рассматриваемом в этом разделе примере, описаны следующие объектные модели, необходимые для построения отчета

  • ReportRow
    • Назначение: Внутренняя модель, представляющая одну строку в итоговом отчёте. Это данные, которые будут сериализованы в JSON и возвращены как результат выполнения скрипта.
    • Ключевые свойства:
      • Type (string) - Тип документа.
      • Product (string) - Обозначение версии документа.
      • Name (string?) - Наименование версии документа.
      • Version (string?) - Номер версии документа.
      • FileName (string) - Имя файла.
      • FileSize (string) - Форматированный размер файла (например, "192 КБайт").
  • ObjectInfo
    • Назначение: Представляет информацию о версии объекта, полученную от сервера.
      Используется в методах GetPropObjects и GetLinkedFast.
    • Ключевые свойства:
      • VersionId (int) - Идентификатор версии объекта.
        • Маппится на поле _ID_VERSION.
      • TypeName (string) - Название типа объекта.
        • Маппится на поле _TYPE.
      • IsDocument (int) - Признак, основан ли объект на документном типа.
        • 0 - нет;
        • 1 - да.
        • Маппится на поле _DOCUMENT.
      • Product (string) - Обозначение объекта.
        • Маппится на поле _PRODUCT.
      • Version (string) - Номер версии объекта.
        • Маппится на поле _VERSION.
  • FileInfo
    • Назначение: Представляет информацию о файле, прикреплённом к документу.
      Используется в методе GetInfoAboutVersion (в режиме вывода 7).
    • Ключевые свойства:
      • Name (string) - Имя файла.
        • Маппится на поле _NAME.
      • Size (long) - Размер файла в байтах.
        • Маппится на поле _SIZE.
  • AttributeInfo
    • Назначение: Представляет атрибут версии объекта.
      Используется в методе GetInfoAboutVersion (в режиме вывода 3).
    • Ключевые свойства:
      • Id (int) - Идентификатор атрибута.
        • Маппится на поле _ID.
      • Name (string) - Название атрибута.
        • Маппится на поле _NAME.
      • Value (string) - Значение атрибута.
        • Маппится на поле _VALUE.

AppConfiguration.cs

Этот файл отвечает за парсинг, валидацию и хранение всех конфигурационных данных, поступающих в скрипт через аргумент configRawData.

  • Класс AppConfiguration
    • Назначение: Является центральным хранилищем конфигурации приложения.
      Он инкапсулирует логику извлечения параметров из десериализованного JSON.
    • Ключевые свойства:
      • ObjectIds  - Список идентификаторов корневых объектов.
        Заполняется из поля object_ids JSON.
      • Parameters (Dictionary) - Словарь пользовательских параметров (например, "Глубина разузловки", "Название типа связи для отбора объектов").
        Заполняется из поля params JSON.
    • Ключевые методы:
      • Create(string rawData): Статический метод, который является точкой входа для инициализации конфигурации.
        Десериализует входящую JSON-строку rawData в объект AppConfiguration с использованием глобальных настроек Global.JsonSerializerOptions.
        Возвращает сконфигурированный объект.
      • GetMainObjectId(): Возвращает первый идентификатор из списка ObjectIds.
        Выбрасывает исключение, если список пуст.
    • В рассматриваемом в этом разделе примере, реализованы дополнительные методы для получения параметров отчета
      • GetMaxDepth(): Извлекает значение параметра "Глубина разузловки" из словаря Parameters, парсит его в int и возвращает.
        Выбрасывает исключение, если не удалось получить значение данного параметра.
      • GetSelectingObjectsLinkTypeName(): Извлекает и возвращает строковое значение параметра "Название типа связи для отбора объектов".
        Выбрасывает исключение, если не удалось получить значение данного параметра.
      • GetSelectingDocumentsLinkTypeName(): Извлекает и возвращает строковое значение параметра "Название типа связи для отбора документов".
        Выбрасывает исключение, если не удалось получить значение данного параметра.

Mapper.cs

Этот класс представляет собой удобную обёртку над низкоуровневыми библиотеками Ascon.Plm.DataPacket и Ascon.Plm.Mapping.
Его задача - преобразовать бинарные данные (byte[]) в формате DataPacket, возвращаемые Server API, в строго типизированные объекты C#.

  • Статический класс Mapper
    • Назначение: Скрывает сложность работы с DataPacketReader и DbMapper, предоставляя простые и понятные методы для маппинга данных.
    • Ключевые методы:
      • private static DataPacketReader CreateReader(object data): Приватный вспомогательный метод.
        Проверяет, что входной объект data является массивом байт (byte[]), и создаёт на его основе экземпляр DataPacketReader.
        Выбрасывает исключение ArgumentException в случае ошибки.
      • public static T FirstOrDefault(object data) where T : class: Обобщённый метод.
        Создаёт DataPacketReader из переданных данных и возвращает первый элемент последовательности, преобразованный в тип T.
        Если последовательность пуста, возвращает null.
      • public static List ToList(object data) where T : class: Обобщённый метод.
        Создаёт DataPacketReader из переданных данных и преобразует все записи в список объектов типа T.
    • Зачем это нужно:
      • Методы Server API (например, GetPropObjects, GetLinkedFast) возвращают данные в виде object.
      • На самом деле этот object является массивом байт (byte[]) в формате DataPacket.
      • Класс Mapper инкапсулирует всю логику по созданию DataPacketReader из этих байт и использованию DbMapper для создания типизированных объектов, что значительно упрощает код в остальных классах.

LoodsmanServerApiClient.cs

Этот файл содержит класс, инкапсулирующий всю логику прямого взаимодействия с сервером приложений ЛОЦМАН:PLM через библиотеку Ascon.Plm.ServerApi.

  • Класс LoodsmanServerApiClient
    • Назначение: Предоставляет методы для вызова конкретных функций Server API.
      Является абстракцией над транспортным уровнем и низкоуровневыми вызовами.
    • Приватное поле:
      • private readonly IConnection _connection: Хранит активное соединение с сервером приложений, инициализируемое в конструкторе.
    • Конструктор:
      • public LoodsmanServerApiClient(string serverAddress, Guid sessionId):
        • Парсит адрес сервера приложений с помощью UriBuilder.
        • Создаёт фабрику подключений ConnectionFactory, передавая идентификатор сессии.
        • Создаёт активное соединение IConnection с помощью CreateConnection.
      • Важное замечание: В текущей реализации не требуется вызов метода SetFormat("Json").
        Библиотека Ascon.Plm.ServerApi по умолчанию возвращает данные в нативном бинарном формате DataPacket, который затем эффективно обрабатывается классом Mapper.
    • В рассматриваемом в этом разделе примере, реализованы дополнительные методы для получения информации, необходимой для построения отчета
      Все методы используют _connection.MainSystem для вызова функций API и передают результа в класс Mapper для преобразования.
      • public ObjectInfo GetObjectInfo(int objectId): Получает информацию об объекте.
        Вызывает метод GetPropObjects.
        Возвращает один объект ObjectInfo или выбрасывает исключение.
      • public List GetDocumentFiles(int documentId): Получает список файлов документа.
        Вызывает метод GetInfoAboutVersion в режиме вывода 7. Возвращает List.
      • public List GetLinkedObjects(int versionId, string linkType): Получает список дочерних объектов по указанной связи.
        Вызывает GetLinkedFast.
        Возвращает List.
      • public string? GetObjectName(int objectId): Возвращает значение атрибута "Наименование" для указанного объекта.
        • Сначала вызывает приватный метод GetObjectAttributes.
        • Затем ищет в полученном списке атрибут с именем "Наименование" и возвращает его значение.
      • private List GetObjectAttributes(int versionId): Приватный метод. Получает список атрибутов версии объекта.
        Вызывает GetInfoAboutVersion в режиме вывода 3.
        Возвращает List.

ReportService.cs

Содержит основную бизнес-логику скрипта: рекурсивный обход дерева объектов и формирование итогового списка строк отчёта.

  • Класс ReportService
    • Назначение: Сервис, который использует LoodsmanServerApiClient для сбора данных и преобразует их в модель ReportRow.
    • Приватные поля:
      • _apiClient: Клиент для взаимодействия с API сервера приложений ЛОЦМАН:PLM.
      • ReportRows: Временное хранилище (список) для накопления строк отчёта в процессе рекурсивного обхода.
    • Ключевые методы:
      • public List GenerateReportData(...): Главный публичный метод.
        В рассматриваемом в этом разделе примере, в методе реализована следующая последовательность действий
        • Получает информацию о корневом объекте через _apiClient.GetObjectInfo.
        • Очищает внутренний список ReportRows.
        • Запускает рекурсивный обход TraverseTree.
        • Возвращает собранный список ReportRows.
    • В рассматриваемом в этом разделе примере, реализованы дополнительные методы необходимые для построения отчета
      • private void TraverseTree(ObjectInfo objectInfo, int currentLevel, int maxDepth, ...): Рекурсивный приватный метод.
        • Базовый случай: Выходит из рекурсии, если currentLevel > maxDepth.
        • Получает наименование объекта через _apiClient.GetObjectName.
        • Обработка документов: Если объект является документом (IsDocument == 1), получает список его файлов через _apiClient.GetDocumentFiles.
          Для каждого файла создаёт и добавляет в ReportRows новую строку с данными о документе и файле.
        • Обход документов-потомков: Получает список связанных документов через _apiClient.GetLinkedObjects с типом связи selectingDocumentsLinkTypeName и
          рекурсивно вызывает для них TraverseTree, увеличивая currentLevel.
        • Обход дочерних объектов: Получает список связанных объектов через _apiClient.GetLinkedObjects с типом связи selectingObjectsLinkTypeName и
          рекурсивно вызывает для них TraverseTree, увеличивая currentLevel.
        • Особенность логики: Если документ не имеет файлов, он не создаёт записей в отчёте, но обход его дочерних документов и объектов продолжается.
          Это позволяет получить файлы из глубоких уровней вложенности.
      • private static string FormatFileSize(long fileBytes): Статический вспомогательный метод.
        • Преобразует размер файла из байтов в человекочитаемый формат (КБайт, МБайт и т.д.).
        • Работает по принципу последовательного деления на 1024 и выбора соответствующей единицы измерения из массива units.

Runner.cs

Этот файл содержит точку входа в библиотеку классов, которую вызывает система отчётов ЛОЦМАН:PLM.

  • Класс Runner
    • Назначение: Управляет всем процессом: от инициализации приложения до вызова сервисов и возврата результата.
    • Статический конструктор:
      • static Runner(): Регистрирует провайдер кодировок (CodePagesEncodingProvider.Instance).
        Это критически важный шаг, без которого методы Server API, возвращающие строки в кодировке Windows-1251, могут выбросить исключение.
        CLR гарантирует, что этот код выполнится один раз и потокобезопасно.
    • Метод Execute:
      • public string Execute(string serverAddress, Guid sessionId, string configRawData): Основной метод, который является точкой входа для системы отчётов.
      • Логика работы:
        • Конфигурация: Создаёт объект AppConfiguration с помощью статического метода Create, передавая ему configRawData.
        • Извлечение параметров: Получает из конфигурации все необходимые параметры
        • Инициализация API-клиента: Создаёт экземпляр LoodsmanServerApiClient, передавая ему serverAddress и sessionId.
        • Инициализация сервиса: Создаёт экземпляр ReportService, передавая ему apiClient.
        • Генерация отчёта: Вызывает метод GenerateReportData у reportService с полученными параметрами.
        • Вывод результата: Сериализует полученный список ReportRow в JSON с использованием глобальных настроек Global.JsonSerializerOptions и возвращает полученную строку.
