Этот раздел описывает архитектуру и ключевые компоненты шаблона скрипта для ЛОЦМАН:PLM.
Понимание структуры этих классов необходимо для разработки новых отчётов и сервисов.

AppConfiguration.cs

Этот файл отвечает за парсинг и хранение всех конфигурационных данных, поступающих в скрипт:

  • адрес сервера приложений
  • список идентификаторов объектов, по которым формируется отчет
  • параметры формирования отчета
  • правила ревизионного конфигурирования
  • другие параметры
  • Класс AppConfiguration
    • Назначение: Является центральным хранилищем конфигурации приложения.
      Содержит как свойства, напрямую полученные из userData (JSON), так и вычисляемые или переопределённые через аргументы командной строки.
    • Ключевые свойства:
      • ApiVersion (string) - версия API сервера приложений. По умолчанию "3".
      • RequestTimeoutSeconds (int) - Таймаут для HTTP-запросов. По умолчанию 60.
      • AppServerHost (string) - Адрес сервера приложений. По умолчанию "http://localhost:8076". Переопределяется аргументом -a при запуске скрипта
      • SessionId (string) - Идентификатор сессии пользователя.
        Переопределяется аргументом --session, при запуске скрипта
      • ObjectIds (List\<int>) - Список идентификаторов объектов, по которым должен быть сформирован отчет. Заполняется из поля object_ids параметра userData.
      • Params (Dictionary\<string, object?>) - Словарь пользовательских параметров (например, "Глубина разузловки", "Тип связи").
        Заполняется из поля params  параметра userData..
      • ConfRules (ConfRules?) - Объект с правилами версионного конфигурирования (может быть null).
        Заполняется из поля conf_rules  параметра userData..
    • Ключевые методы:
      • GetStringParameterByName(string parameterName): Вспомогательный метод для безопасного получения строкового значения из словаря Params. Возвращает string.Empty, если ключ не найден.
      • GetConfiguration(string[] arguments, string? userData): Статический метод, являющийся точкой входа для инициализации конфигурации. Вызывает последовательно DeserializeFromJson и ApplyCommandLineArguments, возвращая полностью сконфигурированный объект AppConfiguration.
      • DeserializeFromJson(string? userData): Приватный статический метод. Десериализует входящую JSON-строку (userData) в объект AppConfiguration. Обрабатывает возможный BOM (Byte Order Mark) и пустые строки.
      • ApplyConfigParameters(AppConfiguration config): Приватный статический метод. Переопределяет свойства ApiVersion и RequestTimeoutSeconds значениями из словаря Params, если они там присутствуют.
      • ApplyCommandLineArguments(AppConfiguration config, string[] arguments): Приватный статический метод. Извлекает аргументы командной строки (-a, --session) и присваивает их соответствующим свойствам объекта config.
      • TryGetArgumentValue(...): Приватный статический метод. Вспомогательный метод для поиска значения конкретного аргумента в массиве аргументов командной строки.
  • Класс ConfRules (вложенный)
    • Назначение: Хранит правила конфигурирования, переданные в userData.
  • Класс RuleParam (вложенный)
    • Назначение: Представляет отдельный параметр правила конфигурирования.

AppClient.cs (LoodsmanApiClient)

Этот файл содержит класс инкапсулирует всю логику взаимодействия с WebAPI сервера приложений ЛОЦМАН:PLM с помощью HttpClient.

  • Класс LoodsmanApiClient : IDisposable
    • Назначение: Предоставляет асинхронные методы для вызова конкретных конечных точек API.
      Является абстракцией над транспортным уровнем.
    • Приватные поля:
      • private readonly HttpClient _httpClient - Базовый HTTP-клиент, инициализируемый в конструкторе. Все методы класса используют его для отправки запросов.
      • private readonly AppConfiguration _config - Хранит ссылку на конфигурацию приложения, которая используется для настройки _httpClient и для передачи параметров в методы API.
    • Инициализация _httpClient:
      • В конструкторе класса на основе _config выполняется настройка _httpClient:
_httpClient = new HttpClient {
         // Собираем базовый адрес из хоста, версии API и стандартного пути "/api/" 
         BaseAddress = new Uri($"{_config.AppServerHost}/api/v{_config.ApiVersion}/"), 

         // Устанавливаем таймаут из конфигурации Timeout = 
         TimeSpan.FromSeconds(_config.RequestTimeoutSeconds) }; 

         // Добавляем обязательный заголовок с идентификатором сессии для аутентификации 
          _httpClient.DefaultRequestHeaders.Add("web-loodsman-session", _config.SessionId);

  • Зачем:

    • BaseAddress позволяет использовать относительные пути в методах, что упрощает код.
    • Timeout предотвращает зависание скрипта при проблемах с сетью.
    • Заголовок web-loodsman-session - это стандартный способ аутентификации для всех запросов к API ЛОЦМАН:PLM.

  • Реализация IDisposable: Класс реализует интерфейс IDisposable, чтобы корректно освобождать ресурсы HttpClient.
    Метод Dispose() вызывает _httpClient?.Dispose().

  • В рассматриваемом в этом разделе примере, реализованы дополнительные методы для получения информации, необходимой для построения отчета

    • GetObjectInfoAsync(int idVersion): Получает информацию об объекте.
      Вызывает GET /ObjectInfo/get-prop-objects.
    • GetLinkedObjectsAsync(int idVersion, string linkType): Получает дочерние объекты по указанному типу связи.
      Вызывает GET /ObjectInfo/get-linked-fast.
    • GetVersionAttributesAsync(int idVersion): Получает атрибуты версии.
      Вызывает GET /ObjectInfo/get-info-about-version-mode-3.
    • GetLinkAttributesAsync(int idLink): Получает атрибуты связи.
      Вызывает GET /ObjectInfo/get-link-attributes-2.

ВНИМАНИЕ! Выше были перечислены методы, добавленные в класс LoodsmanApiClient для реализации скрипта, рассматриваемого в данном разделе Для реализации других скриптов список методов должен быть расширен разработчиком отчетов, по аналогии с реализованными в данном примере.

Models.cs

Этот файл содержит все объектные модели (DTO - Data Transfer Object), используемые для обмена данными между скриптом и Web API сервера приложений ЛОЦМАН:PLM, а также внутренние модели для хранения данных отчёта.

В рассматриваемом в этом разделе примере, описаны следующие объектные модели, необходимые для построения отчета

  • ObjectInfo
    • Назначение: Представляет информацию о версии объекта, полученную от сервера.
      Используется для хранения данных из методов get-prop-objects и get-linked-fast.
    • Ключевые свойства:
      • idLink (int) - Идентификатор связи.
      • idVersion (int) - Идентификатор версии объекта.
      • type (string) - Тип версии.
      • product (string) - Обозначение версии.
      • version (string) - Номер версии.
      • maxCalc (double) - Максимальное расчётное значение (для атрибутов связи, например, количество).
  • Attributes
    • Назначение: Представляет атрибут версии или связи.
      Используется для хранения данных из методов get-info-about-version-mode-3 и get-link-attributes-2.
    • Ключевые свойства:
      • id (int) - Идентификатор атрибута.
      • name (string) - Имя атрибута.
      • value (string) - Значение атрибута.
  • ReportRow
    • Назначение: Внутренняя модель, представляющая одну строку в итоговом отчёте.
    • Ключевые свойства:
      • IdVersion (int) - Служебный идентификатор версии (не выводится в отчёт, но используется для рекурсивных вызовов).
      • IdLink (int) - Служебный идентификатор связи (не выводится в отчёт, но используется для рекурсивных вызовов).
      • Type (string) - Тип версии.
      • Product (string) - Обозначение версии.
      • Name (string) - Наименование версии.
      • VersionNumber (string) - Номер версии.
      • Quantity (double) - Суммарное количество.
      • Weight (string) - Суммарная масса (уже округлённая, как строка).
      • Position (string) - Позиция.

Program.cs

Точка входа в приложение. Здесь происходит сборка всех компонентов, запуск процесса генерации отчёта и вывод результата.

  • Метод Main (асинхронный)
    • Назначение: Управляет выполнением скрипта.
    • Логика работы:
      • Конфигурация: Получает объект AppConfiguration с помощью статического метода GetConfiguration, передавая ему аргументы командной строки (args) и данные из стандартного ввода (Console.In.ReadToEnd()).
      • Инициализация API-клиента: Создаёт экземпляр LoodsmanApiClient, передавая ему сконфигурированный объект config.
      • Инициализация сервиса: Создаёт экземпляр ReportService, передавая ему apiClient и config.
      • Генерация отчёта: Выполняет действия по сбору информации.
        Применительно к примеру, рассматриваемому в этом разделе - вызывает метод GenerateReportAsync у reportService, передавая первый идентификатор из списка config.ObjectIds и значение параметра "Глубина разузловки", полученное из config.
      • Вывод результата: Передаёт полученный список ReportRow в статический метод ReportPrinter.PrintJson, который выводит его в консоль в формате JSON.
      • Обработка ошибок: Блок try-catch перехватывает любые исключения на всех этапах и выводит информацию об ошибке в поток ошибок (Console.Error).

ReportService.cs

Содержит основную бизнес-логику: обход дерева объектов и формирование итогового списка строк отчёта.

ВНИМАНИЕ! Далее будут реализация этого класса будет описана в контексте примера, рассмотренного в этом разделе. Реализация логики формирования данных для конкретного отчета реализуется разработчиком отчетов.

  • Класс ReportService
    • Назначение: Сервис, который использует LoodsmanApiClient для сбора данных и преобразует их в модель ReportRow.
    • Приватные поля:
      • _apiClient: Для выполнения запросов к API.
      • _config: Для доступа к параметрам пользователя.
      • _reportTable: Временное хранилище (список) для накопления строк отчёта в процессе рекурсивного обхода.
    • В рассматриваемом в этом разделе примере, класс реализует следующие методы :
      • Task GenerateReportAsync(int rootIdVersion, int maxDepth): Главный публичный метод.
        • Получает информацию о корневом объекте.
        • Запускает рекурсивный обход TraverseTreeAsync.
        • Запускает обогащение данных EnrichReportDataAsync.
        • Сортирует результат, помещая корневой объект на первую позицию.
      • TraverseTreeAsync(ObjectInfo currentObject, int currentLevel, int maxDepth): Рекурсивный приватный метод.
        • Создаёт ReportRow из currentObject и добавляет в _reportTable.
        • Проверяет условие выхода (currentLevel >= maxDepth).
        • Получает список дочерних объектов через _apiClient.GetLinkedObjectsAsync.
        • Для каждого дочернего объекта вызывает TraverseTreeAsync, увеличивая currentLevel.
      • EnrichReportDataAsync: Приватный метод.
        • Проходит по всем строкам в _reportTable.
        • Для каждой версии объекта получает атрибуты через _apiClient.GetVersionAttributesAsync, извлекает "Наименование" и "Массу".
        • Для каждой связи получает атрибуты через _apiClient.GetLinkAttributesAsync, извлекает "Позицию".
      • CalculateTotalWeight(string weightStr, double quantity): Приватный вспомогательный метод.
        • Парсит строку с массой.
        • Вычисляет totalWeight = weight * quantity.
        • Округляет результат до указанного в конфигурации количества знаков (_config.GetStringParameterByName("Количество знаков после запятой")) и возвращает как строку.

ReportPrinter.cs

Статический класс-утилита для форматирования и вывода результатов.

  • Класс ReportPrinter
    • Назначение: Предоставляет единый способ для вывода данных в консоль в формате JSON.
    • Приватное статическое поле _options: Содержит предопределённые настройки для JsonSerializer, чтобы вывод был отформатирован (с отступами) и корректно обрабатывал русские символы (UnsafeRelaxedJsonEscaping).
    • Публичный статический метод PrintJson(IEnumerable items):
      • Проверяет, что входные данные не null и не пусты.
      • Сериализует коллекцию в JSON с использованием настроек _options.
      • Выводит полученную JSON-строку в консоль с помощью Console.WriteLine.
